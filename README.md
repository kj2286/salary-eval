# 수학비서 · IT 직군 평가 / 등급 산정 앱

**레벨(직무등급)별 기대치**로 분기마다 평가하고, **상대평가**로 연 1회 등급과
**권장 인상률(%)** 을 낸다.

> ⚠️ **이 앱은 연봉 금액을 다루지 않는다.**
> 평가는 리더가 하고 금액은 HR 만 안다. 산출물은 등급과 인상률(%)까지이며,
> 실제 금액 확정은 HR 이 시장 대비 위치(compa-ratio)와 재원을 반영해 진행한다.

- **스택**: Vite + React 19 + Tailwind CSS 4 + lucide-react (백엔드 없음)
- **데이터**: 전부 브라우저 `localStorage`. 서버 전송은 Google Sheets 웹훅을 설정한 경우에만 발생
- **공개 URL**: https://kj2286.github.io/salary-eval/

## 실행

```bash
npm install
npm run dev       # http://localhost:5180
npm run build     # dist/ 정적 산출물
npm run deploy    # GitHub Pages 재배포
```

| 요소 | 출처 프레임워크 | 이 앱의 구현 |

## 평가 구조

### 1) 레벨이 먼저다

레벨은 **연차가 아니라 하는 일의 범위**로 정한다. 레벨이 하는 일은 세 가지다.

1. 같은 문항이라도 **"3점(기대 충족)"의 의미**를 다르게 만든다
2. **도메인 가중치**를 다르게 준다
3. 승급 시 **별도 인상률**이 붙는다 (담당 범위 자체가 달라지므로)

| 레벨 | Radford | 영향 범위 | 성과 | 전문성 | 협업 | 리더십 |
|---|---|---|---:|---:|---:|---:|
| L1 신입 | P1 Entry | 과업 단위 | 25% | 45% | 30% | — |
| L2 주니어 | P2 Developing | 기능 단위 | 30% | 40% | 25% | 5% |
| L3 미들 | P3 Career | 제품 영역 단위 | 35% | 30% | 20% | 15% |
| L4 시니어 | P4 Advanced | 팀 단위 | 30% | 25% | 20% | 25% |
| L5 리드 | P5 Expert / M3 | 조직 단위 | 25% | 20% | 20% | 35% |

가중치가 0인 도메인의 문항은 **화면에 아예 나오지 않는다**. 신입에게 "조직 기여도"를 묻고
3점을 주는 건 평가가 아니라 노이즈다. 그래서 문항 수가 레벨별로 다르다 (L1 8개 → L4·L5 11개).

### 2) 문항은 공통역량 + 직무역량

- **공통 (전사 동일)** — 협업 3문항, 리더십 3문항(`mentor` L2↑ / `direction` L3↑ / `impact` L4↑)
  직군이 달라도 기준이 같아야 "FE의 A와 디자이너의 A가 같은 A인가"에 답할 수 있다.
- **직무 (PD/FE/BE/AI)** — 성과 2문항 + 전문성 3문항

### 3) 채점은 가중합

```
도메인 점수 = 그 도메인 문항들의 평균
최종 점수  = Σ(도메인 점수 × 레벨별 가중치)
```

단순평균이 아니라 도메인 평균을 먼저 내므로 도메인별 문항 수가 달라도 왜곡되지 않는다.

### 4) 등급 — 상대평가

등급은 **평가 대상 집단 내 순위**로 배분한다. 절대 컷오프만 쓰면 평가자 관대화를
통제할 장치가 없다.

| 등급 | 목표 분포 | 권장 인상률(재원 4.5% 기준) |
|---|---|---|
| S 탁월 | 10% | 7.0 ~ 10.0% (기본 8.0%) |
| A 우수 | 25% | 5.0 ~ 7.0% (기본 6.0%) |
| B 기대 충족 | 45% | 3.0 ~ 5.0% (기본 4.0%) |
| C 개선 필요 | 15% | 1.0 ~ 3.0% (기본 2.0%) |
| D 미흡 | 5% | 0% (동결) |

목표 분포로 가중하면 기대 인상률 **4.4%** — 2026년 한국 평균 4.6%와 맞는다.

**배분 규칙**

- 목표 인원은 **최대잉여법**으로 환산한다 (4명 조직이면 S0 / A1 / B2 / C1).
- **동점자는 반드시 같은 등급**을 받는다. 동점 그룹이 경계를 걸치면 그 그룹의 다수가
  속한 등급으로 몰아준다. 전원 동점이면 전원 B 가 된다.
- **절대 가드** — 순수 상대평가는 전원이 잘한 팀에서도 누군가를 D 로 만든다.
  - 절대 점수 **4.0 이상**이면 C·D 로 내리지 않는다 (최소 B)
  - 절대 점수 **2.5 미만**이면 S·A 로 올리지 않는다 (최대 C)
  - 가드를 걸면 순위 역전이 생길 수 있으므로 clamp 후 **단조성을 다시 강제**한다.
    (그래야 "2.40점 C, 2.20점 B" 같은 일이 없다)
- 비교 집단은 정책에서 **전체 / 직무별 / 레벨별** 중 고른다. 10~20명 규모의 기본값은 전체.

분기 평가 화면의 등급은 **잠정값**이다. 아직 채점되지 않은 사람이 들어오면 바뀐다.
최종 등급은 연간 확정에서 정해진다.

## 인상률 산정

```
최종 인상률 = 성과 인상(등급별 밴드) + 승급 인상
```

승급 인상: L1→L2 +5% · L2→L3 +7% · L3→L4 +8% · L4→L5 +10%

둘을 섞으면 본인에게 "성과 때문인지 승급 때문인지"를 설명할 수 없고 이듬해 기준선이
왜곡된다. 추천값과 다르게 확정하려면 **사유 메모가 필수**다 (없으면 확정이 막힌다).

재원(`평가 정책`)을 바꾸면 밴드 전체가 비례해 조정된다.

### 여기서 끝, 나머지는 HR

이 앱의 산출물은 **인상률(%)** 까지다. HR 이 실제 금액을 확정할 때 확인할 것:

- 시장 대비 위치(compa-ratio)에 따른 미세조정 — 밴드 하단은 상향, 상단은 하향
- 최저임금 연환산 하한 (2026년 25,882,560원)
- 포괄임금·고정연장수당 계약이면 통상임금 재산정 필요 여부
- 총 인상 재원 대비 실제 소요액

### 직전 대비 증감

평가는 절대 점수보다 **"지난번보다 나아졌나"** 가 중요하다. 모든 화면에 직전 대비가 붙는다.

- 분기 평가: 직전 분기 대비 점수 변화 (`+0.40 (+12.5%)`)
- 연간 확정: 직전 연도 대비 점수·등급·인상률 (`B → A`, `+2.0%p`)
- 표에도 열로 들어가고, CSV 내보내기에도 포함된다

### 주기: 분기는 평가, 연 1회는 등급 확정

연간 등급은 그 해 저장된 분기 평가의 평균이고, **미평가 분기를 3점으로 채우지 않는다**
(관대화 방지). 평가 분기가 2개 미만이면 경고한다.

## 가드레일

`lib/compliance.js` 가 확정 직전에 점검한다. `block` 은 확정 자체를 막는다.

| 점검 | 수준 | 근거 |
|---|---|---|
| 인상률 음수(삭감) 차단 | block | 취업규칙 개정만으로 이미 정한 연봉액을 깎을 수 없다. 근기법 §94, 대법 2023.5.11. 전합. 삭감은 개별 동의 사안 |
| C·D 등급 근거 메모 누락 | block | 저성과 처우는 다툼 시 회사가 합리성을 소명해야 한다 |
| 추천 인상률 이탈 시 사유 누락 | block | 예외를 남기면 다음 사이클에 기준이 무너진다 |
| 평가 분기 2개 미만 | warn | 한 분기 결과로 연간 등급을 확정하면 단기 이슈가 과대 반영 |
| 승급 없이 15%↑ 인상 | warn | 보통 레벨이 잘못 매겨져 있었다는 뜻 |

금액 관련 점검(최저임금·밴드 이탈)은 여기 없다. 이 앱이 금액을 모르기 때문이며,
HR 단계에서 해야 한다.

상시 고지: 이 앱은 금액을 저장하지 않음 / 평가는 개인정보 / 등급은 집단 상대평가라
집단이 바뀌면 달라질 수 있음.

## 사용 흐름

1. **직원 등록** — 이름·직무·**레벨**. 연봉은 입력하지 않는다.
2. **평가 정책** (헤더) — 상대/절대, 비교 집단, 목표 분포, 절대 가드, 인상 재원.
3. **분기 평가** — 분기마다 같은 직원을 평가. 도메인 가중치·레벨별 기대 행동·직전 분기 대비가
   함께 표시된다. 등급은 잠정값.
4. **연간 등급 확정** — 그 해 분기 평균 → 상대평가 등급 → 권장 인상률.
   승급 검토와 가드레일 점검 후 확정한다.
5. **캘리브레이션** — 절대 가드가 개입한 케이스와 경계에 근소차로 갈린 쌍을 조정 회의에서 본다.
6. **HR 전달** — CSV/시트 내보내기에는 등급·순위·직전 대비·인상률(%)만 담긴다.

## 데이터 · 마이그레이션

- 저장 키는 `salary-eval:*:v4`. 앱을 처음 열 때 v2/v3 데이터가 있으면 자동 이관한다.
- **v3 → v4: 연봉 금액 필드를 옮기지 않는다** (`currentSalary` / `baseSalary` / `newSalary` / 밴드).
  등급·점수·인상률은 그대로 보존된다.
- v3 키는 지우지 않으므로 예전 데이터가 필요하면 브라우저 저장소에 그대로 남아 있다.
- v2 데이터는 레벨 개념이 없어 **전원 L2(주니어)** 로 들어오고, 항목이 바뀌었으므로 개별 점수는
  복원하지 않고 평균만 살려 `구버전 기록` 으로 표시한다.
- 내보내기(CSV/TSV/JSON) 어디에도 금액이 들어가지 않는다 — 파일이 공유돼도 연봉이 새지 않는다.

## Google Sheets 연동

시트 → 확장 프로그램 → Apps Script 에 아래를 배포하고 "웹 앱 URL"을 앱에 붙여넣는다.

```javascript
function doPost(e) {
  const sheet = SpreadsheetApp.getActiveSheet()
  const { rows } = JSON.parse(e.postData.contents)
  if (!rows.length) return ContentService.createTextOutput('empty')
  const headers = Object.keys(rows[0])
  if (sheet.getLastRow() === 0) sheet.appendRow(headers)
  rows.forEach((row) => sheet.appendRow(headers.map((h) => row[h] ?? '')))
  return ContentService.createTextOutput('ok')
}
```

브라우저 보안(CORS) 때문에 `no-cors` 로 보내므로 응답을 읽을 수 없다 — 전송 후 시트에서 직접
확인하거나, 확실한 경로가 필요하면 `시트용 복사`(TSV)를 쓴다.

## 한계

- 이 앱은 **법률 자문을 하지 않는다.** 가드레일은 전형적인 분쟁 지점에서 멈춰 세우는 장치일 뿐이다.
- 인원이 적을수록 상대평가의 의미가 약해진다. 5명 조직에서 "S는 10%" 는 0명 또는 1명이라는 뜻이다.
- 등급은 비교 집단에 의존한다. 집단을 바꾸면 같은 점수라도 등급이 달라진다.
- 데이터가 브라우저 localStorage 에만 있다. 공용 PC 사용을 피하고 정기적으로 JSON 백업할 것.
